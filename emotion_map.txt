Layer 1：音频信号驱动（底噪层）
这是"让数字人看起来是活的"的最基础一层。没有这一层，其他动作都像僵尸跳舞。

输入信号：TTS 输出的 PCM 音频流。

驱动什么：

音频特征	映射到的行为	参数
振幅（RMS）​	口型张开幅度	音量越大嘴巴张越大，这是唇形同步的基础
振幅包络	身体上下浮动（呼吸感）	跟随句子节奏的微幅身体 bob
音高（F0）​	眉毛和头部倾斜	高音 → 眉毛微抬 + 头微仰，低音 → 放松
语速	眨眼频率	语速快 → 眨眼少（专注），语速慢 → 眨眼多（放松）
静音段	动作插入点	句与句之间的停顿 → 插入一个较大的手势动作
关键原则：

口型同步是最低要求——VTube Studio 已经内置了这个，直接用它就可以
身体 bob 不是固定频率的震动，而是跟随句子韵律的起伏。人在说话时身体会随着语气轻重自然摇晃
所有 Layer 1 的动作都应该提前衰减——比对应的音频信号早 50-100ms 启动，让人感觉动作是"自发的"而不是"被声音带动的"

Layer 2： 关键字映射
关键词字典：
"比心" / "爱心"      →  播放比心动画
"拜拜" / "再见"      →  挥手动画
"哈哈"{2,}           →  捂嘴笑 / 拍桌笑
"啊这" / "草"        →  扶额 / 愣住
"吓死我了"           →  后仰 + 惊恐表情
"好厉害" / "太强了"   →  鼓掌 + 星星眼
"嗯？" / "什么？"    →  歪头 + 疑惑表情
"呜呜" / "哭"         →  擦眼泪动画
"不好意思" / "对不起" →  鞠躬
"谢谢" + 礼物相关词   →  比心 + 营业微笑
关键词匹配要做的事：
正则优先于精确匹配：哈哈{2,} 匹配"哈哈哈"和"哈哈哈哈哈哈"，表现力不同但触发同一个动作
优先级和互斥规则：一句话触发多个关键词时，只执行优先级最高的那个，或者按顺序叠加（比心+微笑 = 营业表情）
冷却时间：同一个动作不能 3 秒内重复触发。观众看数字人每句话都在挥手会觉得很傻
否定检测：如果「不」出现在关键词前两个词内（"我不比心"），则不触发


Layer 3：结构化标记驱动（编排层）
这是你的 brain.py 已经在做的基础——让 LLM 在输出回复时附带 [emotion:xxx] 标记。

但你需要扩展这个体系。不只是情绪，而是动作层级：

plaintext

标记体系设计：

[emotion:happy|angry|sad|surprised|shy|serious|bored|teasing]
   → 映射到持续的表情状态（不是一闪而过的动画）

[action:wave|bow|point|clap|facepalm|heart|shrug|nod|shake_head]
   → 一次性动作，播完回到 idle

[gesture:emphasize|thinking|explaining|reacting]
   → 辅助手势，影响手部运动但不打断当前表情

[intensity:0.5-1.0]
   → 动作幅度控制（轻声笑 vs 爆笑）

[duration:short|medium|long]
   → 动作/表情的持续时间
LLM 输出示例：

plaintext

[emotion:excited] 天哪这个礼物太豪华了吧！
[action:heart][intensity:0.9] 谢谢老板！！！
[emotion:teasing] 不过你花这么多钱，下个月吃土可别来找我~
为什么比纯关键词好：

LLM 知道上下文——它能判断"是真的惊喜还是阴阳怪气"，关键词做不到
可以提前决定动作——说出来之前表情已经到位了，这像真人（人先说后笑是装的，先笑后说才是真的）
但这一层有致命问题：

标记格式碎且容易出错（LLM 偶尔不输出标记、输出错格式、标记和文本不对应）
你需要在 brain.py 里做格式校验和 fallback
LLM 对抽象肢体语言的理解是文本的，不是身体的——它知道"人生气会皱眉"但不知道皱眉需要拉动哪些 Live2D 参数


Layer 4：AI 语义驱动（理解层）
对话场景	LLM 理解的意图	行为模型的决策
观众说"主播好菜"	intent: being_teased	先愣了一下（0.3s）→ 鼓起腮帮 → 叉腰 → "你行你上啊！"
聊到感人的回忆	intent: nostalgic_sharing	表情变柔和 → 眼神看远处 → 语速放缓 → 说完后轻轻叹气
冷场 15 秒	intent: idle_bored	开始哼歌 → 身体左右晃 → 看看弹幕 → 突然指屏幕"啊有人说话了"
观众在吵架	intent: moderating	皱眉 → 双手下压（"冷静"手势）→ 严肃脸 → "你们别吵了"
意图不是单标签，是状态向量：

plaintext

intent 不是简单的"happy"或"sad"，
而是一个组合状态：

{
  "valence": 0.7,        # 正面/负面情绪
  "arousal": 0.4,         # 激动/平静
  "dominance": 0.6,       # 掌控/顺从
  "social_mode": "banter", # 社交模式：闲聊/认真/吐槽/安抚/营业
  "energy": 0.5            # 当前精力值
}
行为模型根据这个意图向量做程序化动作生成——不是播固定动画，而是实时混合多个动画层：

plaintext

idle 呼吸基础动画 (始终在跑)
+ 情绪表情层 (根据 valence+arousal 混合)
+ 手势层 (根据 social_mode 选择手势集合)
+ 头部朝向 (根据注意力目标——屏幕/弹幕/镜头)
+ 随机微动作 (眨眼、舔嘴唇、摸头发，2-8秒随机触发)
这一层的难点：

需要 LLM 额外输出意图分析（增加一次 API 调用或延长输出）
行为模型需要精细设计，不是简单的"happy=微笑"
延迟是敌人——从理解意图到身体做出反应，每一步都在消耗宝贵的直播响应时间
